## Quick Non-Negotiable Reminders
- **Zero Production Mocks / Silent Fallbacks & Agent-Only Generation (`D28`):** Fail closed and loudly with typed `ErrorCode` diagnostics (`schemas/v2/error-codes.json`, `34` codes including `422 AGENT_NOT_CONFIGURED`, `409 PROJECT_JOB_ACTIVE`, `429 BUDGET_EXCEEDED`). Never silently swallow server errors or substitute synthetic production fallbacks.
- **Loopback Open Access & Remote Guard (`D18`):** Loopback requests run zero-auth with no token/cookie/CSRF login steps; `opendv serve` refuses non-loopback `--host` with exit code `40` unless `--allow-remote-unauthenticated` is explicitly supplied.
- **Cross-Transport Parity & Unified 4-Tab Workbench Routes:** Unified `opendv` CLI, FastAPI (`/api/v1/...`), `opendv mcp serve`, and the 4-tab `:8420` `web/` Workbench (`Project Workflow`: `/projects/:id/step/1..7` in `Guided ⇄ Observatory` with `Budget Meter`; `DV Schema Explorer`: `/projects/:id/explorer` using **5-Zone (`Z0–Z4`)** + `information_mart`; `Run Explorer`: `/projects/:id/runs`; `Settings`: `/settings`) must agree strictly on `schemas/v2/{cli-spec,error-codes,openapi,baseline-digests}.json`, `StrictModel` (`extra="forbid"`) DTOs, and canonical RFC 8785 JCS SHA-256 digests (V2 `0.0.0` genesis = `0ae856bf9fdba74e83e793ea9f74106a0c14d21d73756e1e3a12abd426d0083a`).
- **Modular `< 5,000`-Token Ceiling (`D16`) & Workspace Hygiene:** Keep every active `.py`/`.ts`/`.tsx` module in `src/opendv/`, `tests/conftest.py`, `tests/helpers/`, and `web/src/` strictly `< 5,000` `cl100k_base` tokens (`tests/architecture/test_module_token_budget.py`). Never write scratch notes, critique dumps, or temporary scripts into tracked folders (`scripts/`, `reports/`, or repo root). Always verify `git status --short` and run the verification suites before completing work.
- **Ponytail Minimal Complete Change & Attribution:** Climb the 6-rung simplicity ladder before adding abstractions, never cut trust-boundary/security/data-loss/a11y validation (`Never cut:`), mark bounded deferrals with `shortcut: <limit>, <upgrade trigger>`, and end implementation replies with what was skipped/not checked and risks. *(Ponytail rules/skills vendored from [`@dietrichgebert/ponytail`](https://github.com/DietrichGebert/ponytail) v5.3.3, Dietrich Gebert, MIT License.)*
- **Complete Component Documentation Suite (`REQ-DOC-01`):** Every new or refactored component must ship and maintain all four living documents—a Component README (`docs/components/<component>/README.md`), User Guide (`user-guide.md`), Architecture Design Doc (`docs/designs/`), and Contributor Guide (`contributor-guide.md`)—linked from [`README.md`](README.md) and validated by `tests/docs/` (see [`docs/components/modeling/README.md`](docs/components/modeling/README.md) as the reference suite).
