# ADR-013: Async SSE Event Streaming with `Last-Event-ID` Cursor Replay

## Status
Proposed

## Context
Long-running tasks (parsing, OCR, agent reasoning, BM25 indexing) take 5s–3m. Synchronous requests risk HTTP timeouts and lack progress visibility. SSE works over standard HTTP without WebSocket proxy complexity.

## Decision
We implement asynchronous task execution with W3C Server-Sent Events (SSE) scoped per session:

### 1. Unified REST Route Topology & CLI Exit Code Mapping
- Base path is `/api/v1/ontology/studio`:
  - `POST .../sessions/{id}/{parse|clarify|construct}` -> Returns `202 Accepted` with `job_id`. Non-streaming CLI calls exit 0 on 202; `--auto-commit` implicitly enables `--wait`.
  - `GET .../sessions/{id}/jobs/{job_id}` -> Status JSON; `GET .../sessions/{id}/jobs/{job_id}/events` -> Live SSE stream. With `--stream` or `--wait`, CLI monitors until terminal event; on success exits 0; on failure resolves exit code via `schemas/v1/error-codes.json`.
  - `POST .../sessions/{id}/jobs/{job_id}/cancel` -> Cooperative cancellation.

### 2. Append-Only JSONL Event Journaling & `Last-Event-ID` Replay
- Events appended to `jobs/<job_id>.events.jsonl` in $O(1)$ time with monotonic integer `id` (`1, 2, 3...`).
- Headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache` (`Connection: keep-alive` on HTTP/1.1; omitted on HTTP/2+). 15s keepalive comments prevent proxy timeouts.
- Reconnection: `Last-Event-ID: <id>` replays journal events where `id > Last-Event-ID`.
- Terminal journals > 50 MB compress under `.journal_<job_id>.lock` via staged `.staging-<uuid>.events.jsonl.gz`, fsync, and `os.replace`. Replay concatenates `.events.jsonl.gz` then `.jsonl` deduplicating by `id > last_seen_id`. Capability errors (`OCR_UNAVAILABLE`, `OFFICE_CONVERSION_UNAVAILABLE`) append as terminal events.

### 3. Cooperative Cancellation & Startup Crash Recovery
- `/cancel` sends abort signal. If version commit begun, rejected with `409 Conflict` (`JOB_COMMIT_IN_PROGRESS`).
- **Startup Crash Recovery with Job Leases (ADR-009)**: Non-blocking `.job_<job_id>.lock` inspects non-terminal jobs. If acquired, worker abandoned lease: status `JOB_ABANDONED_SERVER_CRASH` (500, exit 1). Heartbeat in `<jid>.json` > 5m while held reports `stalled`.

## Consequences & Compliance
W3C SSE cursor replay; 15s keepalive; transparent `.gz` replay. Tests verify SSE emission, cursor replay, and cancel rejection during commit.
