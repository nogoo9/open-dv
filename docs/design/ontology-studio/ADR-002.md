# ADR-002: Dual-Mode Construction Engine (Deterministic Fallback + 3-Persona LLM Agent)

## Status
Proposed

## Context
Constructing Graph A ontologies requires semantic reasoning. While LLMs excel at synthesis, air-gapped networks and CI runners require zero-API-key execution without network flakiness or cost.

## Decision
We implement a **Dual-Mode Construction Engine** in `packages/opendv-service`:

### 1. Agent-First Mode (Primary)
Operates via three personas: `@term-scout` (`FAST`; extracts terms); `@domain-clarifier` (`HIGH_REASONING`; emits questions); and `@ontology-architect` (`HIGH_REASONING`; synthesizes CBCs, grounds to FIBO, emits additive deltas).

### 2. Deterministic Fallback Pipeline (Zero-API-Key)
Supports `--mode {auto|agent|deterministic}`: `auto` falls back to deterministic in zero-key setups; `agent` requires credentials (missing -> `AGENT_UNAVAILABLE` 503 exit 1); `deterministic` runs offline via BM25, schema heuristics (`_id`, `_pk`, `_fk`, `_ts`), and additive deltas. Auto-commit records `actor=resolved_mode`, `triggered_by=principal`, subject to Server Grounding (ADR-007 §2). Proposals set `proposer_actor = resolved_mode`, `proposer_principal = f"{resolved_mode}:{job_id}"`, `triggered_by = principal`; human accept sets `actor="human"`, `accepted_by=principal`. Both record `construction_mode` in `meta.json`.

## Consequences & Compliance
Zero-credential offline availability; agent reasoning when configured; auditable provenance. CI runs deterministic mode live and agent mode against replay fixtures (injected strictly via test fixtures; `src/` never imports `tests.support`).
