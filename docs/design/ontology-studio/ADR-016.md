# ADR-016: Data Protection, Redaction Boundary, RBAC Clearance & Archive Security

## Status
Proposed

## Context
Enterprise documents contain PII, MNPI, and secrets. External LLMs risk data leakage, while local endpoints face unauthenticated access and DNS rebinding.

## Decision
We establish a strict Data Protection, Redaction, and Archive Security Boundary:

### 1. Pre-LLM Redaction, Bounded Excerpts & Derived Taint Propagation
- **Enforcement Location**: Redaction and privacy boundaries are enforced in `opendv_service.studio.redaction`, strictly before prompt assembly for persona harnesses (`@term-scout`, `@domain-clarifier`, `@ontology-architect`).
- **`do_not_send_to_agent` & Taint Redaction**: In `manifest.json`, `do_not_send_to_agent=True` suppresses raw text (write-once; admin clear logs to `audit.jsonl`). `taint_index.json` maps entities to `source_sha256`; missing evidence fails closed as tainted. Tainted entities scrub text to `"[REDACTED_ODV_CONFIDENTIAL_SOURCE]"` in prompts/logs (CAS/exports unscrubbed; tainted exports logged to `audit.jsonl`).
- **BM25 Search & HMAC Pseudonymization**: Tainted BM25 runs server-side; `matched_term` scrubbed to `"[REDACTED_ODV_CONFIDENTIAL_SOURCE]"`. HMAC tokens (0600 `.session_secret`): URIs, IDs, slugs per ADR-007 §2. `ExternalMapping.standard_name` suppressed. De-pseudonymization runs on raw agent JSON before parsing to `proposals/<pid>.json`. Proposals/versions never contain pseudonym tokens (unresolved fail `AGENT_UNRESOLVED_PSEUDONYM`). Proposed entities inherit taint.
- **Server Provenance Validation**: Governed by ADR-007 §2: `mapping.provenance` must match `(record.proposer_actor or record.actor)` (forged -> `ONT_EVO_FORGED_PROVENANCE`, 422 exit 4).
- **Automated PII/MNPI Scrubbing & Placeholder Guard**: Scrubbers mask sensitive PII/tax IDs to `[REDACTED_ODV_*]`. Scans reject pipeline placeholders (`\[REDACTED_ODV_[A-Z0-9_]+\]`), failing with `REDACTED_PLACEHOLDER_LEAK` (422, exit 4).
- **Observability Ledger**: Prompts/completions logged to `audit.jsonl` (90-day retention with weekly gzip; secrets masked).

### 2. Session ID, Workspace Path Containment & Path Traversal Guards
- `session_id` validated against `^[a-z0-9_-]{1,64}$` (rejecting Windows devices `(?i)^(con|prn|aux|nul|com[1-9]|lpt[1-9])$` and keywords `(?i)^(import|prune|init|bundle|gc)$`). Paths resolve in `<studio_root>/<session_id>/` (`OPENDV_STUDIO_ROOT`). Traversal returns 400 `INVALID_SESSION_IDENTIFIER`.
- **Workspace Path Containment (`INVALID_WORKSPACE_PATH`)**: Arguments (`--workspace`, `--from-workspace`) must resolve inside `OPENDV_WORKSPACE_ROOTS`. Normalized `p_n = os.path.normcase(os.path.realpath(p))`. Traversal, symlink escapes, UNC, ADS, or `commonpath([p_n, r_n]) != r_n` fail `INVALID_WORKSPACE_PATH` (exit 2; re-checked under `graph_a.lock`). Remote rejects `server_path` (`REMOTE_SERVER_PATH_FORBIDDEN` exit 2).

### 3. Archive Decompression Security Limits
ZIP imports (`.odvstudio.zip`) enforce streaming limits counted on actual decompressed bytes: max 250 MB uncompressed, 500 entries, 100:1 ratio on entries > 1 MB. Directory entries (single trailing '/' and `is_dir()`) are skipped safely. A file entry is rejected (`ARCHIVE_SECURITY_VIOLATION` 422 exit 4) if it starts with '/' or '\', contains '\', has a drive prefix (`^[A-Za-z]:`), contains ':' anywhere, has any path segment equal to '..' or '.', has an internal empty segment, is a symlink, or duplicates an existing entry under NFC and casefold normalization.

### 4. RBAC Clearance, Browser Elevation & Local Admin Token
- **Authentication & Browser Bootstrap**: Auth via `X-OpenDV-Token` or cookie (401 `UNAUTHENTICATED` exit 7). Loopback `POST /init` requires `X-OpenDV-Workbench: 1`, verifies loopback peer (`127.0.0.1`/`::1`), creates `.local_token` (0600; 409 `STUDIO_ALREADY_INITIALIZED` exit 6). Remote disables `/init` and loopback privileges (`LOOPBACK_PRIVILEGE_DISABLED_IN_REMOTE_MODE` 403 exit 7); local binds to loopback (`127.0.0.1`/`::1`). Launch token `/ontology?token=<nonce>` is single-use, consumed atomically (60s TTL), and exchanges for cookie (`SameSite=Strict`, `HttpOnly`, `Secure` on TLS); bootstrap response sends `Referrer-Policy: no-referrer` and `Cache-Control: no-store`; access logs redact `token=`; UI strips token via `history.replaceState`. `studio open` mints `editor` (or `--role viewer`/`admin`). `<studio_root>` enforces 0700/DACL. Client `X-OpenDV-Role` stripped.
- **Safe Browser Elevation Flow**: `/auth/elevate` accepts single-use admin launch nonce from `studio open --role admin`, issuing elevated admin cookie (`SameSite=Strict`, `HttpOnly`, `Secure`, 15m sliding TTL).
- **Host & Origin Validation**: Host allowlist `{"localhost", "127.0.0.1", "::1"}` parses authority per RFC 3986 (handling IPv6); fallback to `X-OpenDV-Token`; remote requires `OPENDV_HOST_ALLOWLIST`. Cookie mutations require verified origin and `X-OpenDV-Workbench: 1` (cross-origin -> 403 `CSRF_ORIGIN_MISMATCH`). Bearer requests skip origin checks.
- **Local Admin Token & Precedence**: `.local_token` (0600/DACL) under `.local_token.lock`. Precedence: (1) `OPENDV_TOKEN`; (2) `OPENDV_LOCAL_TOKEN_PATH`; (3) `<studio_root>/.local_token`. Verified via `hmac.compare_digest` on digests (`human:local_admin`, `admin`, `human`; absent -> `UNAUTHENTICATED` 401 exit 7). `studio token issue --principal <name>` validates `--principal` matches `_P`. `LOCAL_ADMIN_PRINCIPAL` reserved (409 exit 6). Insecure perms fail `INSECURE_STUDIO_ROOT_PERMISSIONS` (exit 1).
- **Normative RBAC Authority**: Governed by `schemas/v1/cli-spec.json` and ADR-012 §1 (`viewer` read-only; `editor` additions/construct; `admin` human only for revisions, waivers, promote, tokens; automated denied direct mutations [403 exit 7]). Automated actors (`agent`/`deterministic`) overwriting non-None metadata reject `AGENT_METADATA_OVERWRITE_FORBIDDEN` (403 exit 7); human overwrites fall through to `*_ALREADY_EXISTS` (exit 4).

### 5. Track Ownership & Traceability
Track 4A (Core contracts/models), Track 4D (Path guards/audit/zip limits), Track 5A (Redaction/taint/PII), Track 5B (HTTP RBAC/Host-Origin/admin token).

## Consequences & Compliance
Sensitive text cannot leak to LLMs; perimeter blocks traversal and archive limits. Self-acceptance forbidden (exit 7); single-issuer setups require loopback override (`--allow-self-accepted-proposals` with `OPENDV_ALLOW_SELF_ACCEPTED_PROPOSALS=1`, import requires `--acknowledge-unverified-import-attribution` exit 4). Tests verify zero leakage, role rejection, taint fail-closed, and traversal rejection.
