# ADR-010: Document Ingestion Pipeline Using Python `liteparse` with `PageMapEntry` and OCR Routing

## Status
Proposed

## Context
Ingesting documents (PDF, CSV, Parquet, Markdown, XLSX) requires character-level evidence grounding without system dependencies; optional OCR/Office conversion degrades to 501 capability errors. Character offsets must not drift across OSes or languages.

## Decision
We implement the Document Ingestion Pipeline using Python `liteparse` with normalized `PageMapEntry` offsets and adaptive OCR routing in `packages/opendv-sources`:

### 1. `PageMapEntry` & `EvidenceRef` Canonical Contracts
Defined in `opendv_contracts.dtos.evidence` inheriting from `BaseContractModel`:
```python
from typing import Self
from pydantic import Field, field_validator, model_validator
from pydantic_core import PydanticCustomError as _Err
from opendv_core.canonical import quantize_confidence
from opendv_contracts.dtos.base import BaseContractModel

class PageMapEntry(BaseContractModel):
    page_number: int = Field(ge=1); start_char: int = Field(ge=0); end_char: int = Field(ge=0); bounding_box: list[float] | None = Field(None, min_length=4, max_length=4); text_snippet: str | None = None; has_tables: bool = False; is_scanned: bool = False
    @model_validator(mode="after")
    def check_offsets(self) -> Self:
        if self.start_char > self.end_char: raise _Err("INVALID_EVIDENCE_OFFSETS", "invalid")
        return self

class EvidenceRef(BaseContractModel):
    source_sha256: str = Field(pattern=r"^[0-9a-f]{64}$"); page_number: int = Field(ge=1); start_char: int = Field(ge=0); end_char: int = Field(ge=1); text_snippet: str = Field("", max_length=1000); confidence: float = Field(1.0, ge=0.0, le=1.0)
    @field_validator("confidence")
    @classmethod
    def validate_confidence(cls, v: float) -> float: return quantize_confidence(v)
    @model_validator(mode="after")
    def check_offsets(self) -> Self:
        if self.start_char >= self.end_char or (self.end_char - self.start_char) > 1000: raise _Err("INVALID_EVIDENCE_OFFSETS", "invalid")
        return self
```
*Taint & Offsets*: Taint builder validates `source_sha256` in `manifest.json`. Offsets `start_char`/`end_char` are Unicode code points in normalized text (`\n`); `page_number` matches enclosing `PageMapEntry`. Service verifies `end_char <= len(normalized_text)` (`EVIDENCE_OFFSET_OUT_OF_RANGE` 422 exit 4; syntax `INVALID_EVIDENCE_OFFSETS` 400 exit 2). Non-empty `text_snippet` matches normalized CAS source; empty snippet is offset-only, excluded from `evidence_grounding` (ADR-007 §2). `evidence/<sha256>.json` records `normalized_text_sha256`, `page_separator="\n"`, `parser_version`; drift fails `INVALID_EVIDENCE_GROUNDING` (exit 4).

### 2. Unicode Offset Normalization & Cross-Language Consistency
- **Text Normalization & Offsets**: Source text normalizes to Unicode NFC and LF (`\n`) before indexing. Offsets count Unicode code points (characters), guaranteeing identical values across runtimes.
- **TypeScript Web UI Conversion**: `@opendv/protocol-ts` converts code points to UTF-16 code units at runtime for DOM selection and PDF canvas rendering, eliminating non-BMP drift.

### 3. Layout Complexity, OCR Routing & Hardened Conversion
- **`is_complex` Threshold & OCR**: Complex (`is_complex = True`) when text density < 50 chars/page or raster area > 40%. Native pages parse via `liteparse` (0.4.x; embedded PDFium for PDF, native tabular, native Markdown; fallback `pypdf`). Complex pages route to Tesseract (missing -> `OCR_UNAVAILABLE` 501 exit 1).
- **LibreOffice Headless Conversion**: Office formats (DOCX, PPTX, XLSX, DOC, PPT, XLS) route to headless LibreOffice (`soffice`) in an isolated profile; missing `soffice` routes to `OFFICE_CONVERSION_UNAVAILABLE` (501 exit 1).

## Consequences & Compliance
Auditable provenance; zero offset drift via NFC/LF. Tests verify `PageMapEntry` on PDF/CSV/Parquet/Markdown and zero drift on non-BMP Unicode characters.
