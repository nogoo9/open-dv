# ADR-009: Server-Side CAS Studio Session Storage in `.opendv/ontology_studio/<session_id>/`

## Status
Proposed

## Context
The Studio manages state across document uploads, async reasoning, domain clarification, human feedback, and version branching. Persistence must be resilient against process crashes, operate without external database daemons, and function robustly on both POSIX and Windows filesystems.

## Decision
We implement Server-Side Content-Addressable Storage (CAS) Session Persistence under studio root (defaults to `<workspace_root>/.opendv/ontology_studio/`, configurable via `OPENDV_STUDIO_ROOT`):

### 1. Storage Architecture & Directory Layout
- **Permissions & VCS Exclusion**: `<studio_root>` and `<session_id>/` enforce POSIX 0700 / owner DACL. Init writes `.gitignore` (`*`). Startup checks `git ls-files --error-unmatch`: tracked fails closed (`INSECURE_STUDIO_ROOT_PERMISSIONS` exit 1), untracked passes; non-repo falls back to traversal.
- `<studio_root>/.local_token`: Admin token (0600 / owner DACL; precedence: `OPENDV_TOKEN` -> `OPENDV_LOCAL_TOKEN_PATH` -> `.local_token`). `.tokens.json` (0600) and `.local_token.lock` under `<studio_root>` excluded from bundles, clones, and GC.
- `<studio_root>/<session_id>/`: Root (`.session.lock`, `.session_secret` [256-bit HMAC 0600, excluded from export], `session.json`, `taint_index.json`, `audit.jsonl`, `feedback.jsonl`); `inputs/` (`manifest.json`, `cas/<sha256>`); `evidence/` (`<sha256>.json` `PageMapEntry`); `clarifications/` (`questions.json`, `answers.json`); `proposals/` (`<proposal_id>.json`); `versions/vX/` (`ontology.yaml`, `ontology.json`, `delta.json`, `meta.json`); `jobs/` (`<job_id>.json`, `<job_id>.events.jsonl`, `.job_<job_id>.lock`).

### 2. Session CAS Storage, Lifecycle & Retention Semantics
- Ingested files stored in `inputs/cas/<sha256>`.
- **Session Creation & Seeding**: `POST /sessions` (`CreateSessionRequest`: `domain_namespace = DEFAULT_DOMAIN_NAMESPACE` matching `^[a-z][a-z0-9_]*$`). Inits `session.json` (`active_version = "0.0.0"`, `head_sha256 = compute_ontology_sha256(genesis_template(params))` in `opendv_core.genesis`). `--from-workspace <p>` derives namespace/owner (`CONFLICTING_WORKSPACE_SEED_PARAMS` exit 1). `session clone` copies CAS and `versions/vX/`, sets `.session_secret` (0600), reconstructs taint, records `cloned_from_session_id`. Seed: `target_sha256 == seed_source_sha256 == compute_ontology_sha256(model)`. Promotion acquires locks per ADR-007 §3.
- `POST /sessions/{id}/construct`: `ConstructRequest(base_version, base_sha256, mode, auto_commit)`. Pins base when auto-committing; stale head -> 412 `ONT_EVO_CONCURRENT_MODIFICATION`. Unpinned jobs snapshot `head_sha256` under `.session.lock` at init (`proposal.base_sha256 = head_sha256`).
- **Lifecycle & GC**: Deletion (`DELETE /sessions/{id}`) and prune (`POST /sessions/prune`) check registry (`CANNOT_DELETE_PROMOTED_SESSION`, `CANNOT_PRUNE_PROMOTED_SESSION`). CAS GC (under `.session.lock`) purges unreferenced blobs, skipping reachable blobs (manifests, `evidence/`, active jobs, PENDING proposals, committed citations). `source remove` fails if cited in committed versions (`SOURCE_REFERENCED_BY_COMMITTED_VERSION` exit 4) or pending proposals (`SOURCE_REFERENCED_BY_PENDING_PROPOSAL` exit 4).

### 3. Multi-File Atomic Commit, Metadata Schema & Crash Recovery
- **Normative DTOs (`opendv_contracts.dtos`)**:
  `ReferencePackPin`: `pack_id: str; pack_version: str; pack_sha256: _H`
  `CreateSessionRequest`: `domain_namespace: str = Field(DEFAULT_DOMAIN_NAMESPACE, pattern=r"^[a-z][a-z0-9_]*$"); enterprise_owner: str = DEFAULT_ENTERPRISE_OWNER; ontology_id: str | None = None; description: str | None = None; from_workspace: str | None = None`
  `ImportProvenanceRecord`: `imported_at: AwareDatetime; imported_by: _P; archive_sha256: _H; claimed_author: _P | None = None; claimed_actor: _L["human"] | _A | None = None; claimed_low_confidence_grounding_waiver: bool = False; claimed_evidence_grounding: list[EvidenceGroundingApproval] | None = None; acknowledged_attribution: bool = False; acknowledgement_rationale: str | None = None`
  `VersionMetaRecord`: `target_sha256: _H; parent_sha256: _H | None = None; commit_timestamp: AwareDatetime; author: _P; mode: _L["seed", "delta", "construct", "proposal_accept", "revision"]; matcher_id: str; matcher_version: str; matcher_sha256: _H; reference_packs: list[ReferencePackPin]; proposal_id: _U | None = None; accepted_by: _P | None = None; low_confidence_grounding_waiver: bool = False; grounding_rationale: str | None = None; low_confidence_waiver_concepts: list[_CU] | None = None; evidence_grounding: list[EvidenceGroundingApproval] | None = None; triggered_by: _P | None = None; historical_contract_warning: str | None = None; requested_mode: _L["auto", "agent", "deterministic"] = "auto"; construction_mode: _A | None = None; seed_source_sha256: _H | None = None; seed_source_file_sha256: _H | None = None; grandfathered_concept_uris: list[_CU] | None = None` (`(mode == "proposal_accept") == bool(proposal_id and accepted_by)` and `(mode == "seed") == bool(seed_source_sha256)`, else `CORRUPT_SESSION_RECORD` exit 1; stored in `versions/vX/meta.json`; immutable; import stores in `import_provenance.json`).
- **Committed Version Immutability**: `versions/vX/` directories are strictly immutable. Staging writes `meta.json` once prior to atomic rename.
- **Atomic Version Commit Protocol**: 1. Acquire `.session.lock` (30s) -> 2. Stage in `.staging-<uuid>/` & atomic rename via `os.replace` (retry 10..250ms, exhausted -> `VERSION_COMMIT_IO_FAILURE` exit 1) -> 3. Roll head forward monotonically (target > active, parent_sha256 == head; genesis 0.0.0 rolls to intact seed root); only proposal in `meta.json.proposal_id` marks `ACCEPTED` (`resolved_at=commit_timestamp`, `resolved_by=accepted_by`) and writes `proposals/<pid>.json` after `os.replace`; roll-forward recovery reconciles unresolved proposals from `meta.json`. Orphaned dirs move to `.quarantine-<ts>-vX/`. Missing metadata or hash failure fails `CORRUPT_SESSION_RECORD` exit 1 -> 4. Update `session.json`.
- **Lock Hierarchy & Crash Recovery**: Total lock order: `.local_token.lock` -> Job Lease (`.job_<jid>.lock`) -> `.journal_<job_id>.lock` -> Workspace Lock (`graph_a.lock`) -> Session Lock (`.session.lock`). Acquiring lease on non-terminal job confirms abandonment (`JOB_ABANDONED_SERVER_CRASH` exit 1); heartbeat > 5m reports `stalled`. `audit.jsonl` retained 90 days with weekly gzip rotation.

## Consequences & Compliance
Atomic replace eliminates torn writes; immutable directories preserve lineage. Tests verify atomic file replacement, retry backoff, CAS isolation, and genesis vectors.
