# ADR-015: Claude CLI Opus 5.5 Critique Loops with 0 CRITICAL and 0 MAJOR Merge Gates

## Status
Proposed

## Context
Autonomous multi-agent development requires high-reasoning review beyond tests to detect architectural layering, hash stability, and ONT-EVO contract edge cases before PRs merge.

## Decision
Mandatory Claude CLI Opus 5.5 Critique Loops with strict 0 CRITICAL and 0 MAJOR merge gates govern the project lifecycle:

### 1. External Critic Invocation Protocol
- Review harness executes via Claude CLI: `claude -p --model claude-opus-5-5` (configurable via `OPENDV_CRITIQUE_MODEL` with allowlist).
- Harness validates model ID and attaches it to output critique report.
- Prompt provides user request, plan, git diff with nonce boundaries (`===UNTRUSTED_DIFF_{nonce}===`), rules, and invariants. Harness validates output JSON schema and computes verdict strictly from counts (`critical == 0 and major == 0`). Python snippets and schemas in ADRs are strictly normative contracts (fields, types, validator invariants, error codes); divergence requires an ADR amendment.

### 2. Critique Trigger Points & Thresholds
- **Trigger Points**: End of every phase (M1..M6) and feature PRs; final whole-branch audit in Phase 6e before PR to `main`.
- **Thresholds**: **0 CRITICAL** and **0 MAJOR** required (`GATE PASSED`). MINOR/SUGGESTION reviewed or ticketed.
- **Quota Fallback**: On rate limits, reports record fallback reviewer as advisory; phase merges remain blocked until Opus 5.5 passes with 0 CRITICAL and 0 MAJOR findings.

## Consequences & Compliance
Strict 0 CRITICAL/MAJOR quality gates; immutable reports. Merge policy requires 0 CRITICAL and 0 MAJOR findings; `scripts/run_opus_critique.py` gates CI.
