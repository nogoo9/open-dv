- **Author:** Eterna2
- **Status:** Approved

## Overview

This specification defines two connected capability areas (detailed across Subsystems 1–4 below) across Open-DV V2 (`src/opendv/`, `web/`, `schemas/v2/`, `tests/`, `pyproject.toml`, `docs/`, `AGENTS.md`, `README.md`, `.agents/skills/open-dv-elephant/`, and `.agents/skills/open-dv-workflow/`):

1. **Per-Provider Harness Readiness (`agy`, `claude-cli`, `claude`, `gemini`):** A lightweight Layer-4 readiness service that runs warm offline prerequisite checks (`< 50ms`, zero tokens), maintains a minimal best-effort `readiness.json` status cache cleared on secret/settings edits and updated passively after completed LLM turns, suppresses manual probes during active provider runs (`409 PROJECT_JOB_ACTIVE`), and executes opt-in live auth probes on demand.
2. **Complete Non-UI CLI Parity, New-Run Project Snapshot Wiring & Structured Remediation:** Full CLI parity across the existing `11` top-level command groups—adding `7` new leaf subcommands (`46 -> 53`: `settings models`, `settings profile {list,set,delete,test}`, and `project settings {show,set}`) alongside user-global secrets and expanded options on `settings set`, `settings trust-workspace --revoke`, and `doctor --probe`—plus Step 4/6 new-run wiring (`cegar_policy`, `discovery_mode`, budgets, `model_overrides`, `v7_critic_tier`) across REST/CLI/Web/MCP, and agent-vs-human `ProblemDetails.remediation` across synchronous HTTP errors, readiness/doctor responses, CLI (`--json` + stderr), stdio MCP, and Web UI alerts.

Because Open-DV V2 is pre-release, no legacy backward-compatibility or V1 migration shims are included. Constitutional rules and sibling architecture docs are indexed in [`AGENTS.md`](../../AGENTS.md) and [`SITEMAP.md`](SITEMAP.md).

## The Problem

Operators and autonomous CLI agents currently configure and run harnesses without accurate feedback, complete controls, or active runtime wiring:

1. **No Harness Visibility Before Failure:** In Web Settings (`/settings`), the **Harness Provider** selector shows four static options with no prerequisite or verification state. On the CLI, `opendv doctor` checks retired `OPENROUTER_API_KEY` and `OPENAI_API_KEY` env vars, ignores `GEMINI_API_KEY` and `GOOGLE_API_KEY`, skips `--extra sdk` package checks (`anthropic`, `google-genai`), and checks client binaries locally even when `--api-url` targets a `:8420` server.
2. **Lost Keyring Keys Across Restarts & Workspace Boundaries:** In `src/opendv/service/secrets.py`, `KeyringSecretStore._known_keys` lives only in process memory, leaving `opendv secrets list` empty after restart, while secrets use workspace-digest isolation (`opendv:{sha256(OPENDV_HOME)}`) instead of user-global scope matching `settings.json` and `mcp_servers.json`. Meanwhile, strict test/schema isolation is incomplete because `export_openapi_schema()`, `pytest`, and child CLI/Playwright processes can read or clobber host OS keyrings.
3. **Unwired Execution Settings & Frozen Project Snapshots:** `WorkspaceSettings` budgets, `model_overrides`, `connection_profiles`, and trust revocation lack CLI parity. `ProjectsService.init_project` drops `model_overrides`, and default `vault build` (`VaultBuildReq.policy = "balanced"`) and `ontology construct` (`OntologyConstructReq.discovery_mode = "incremental_new"`) ignore `ProjectSettingsSnapshot` defaults across REST, CLI, Web, and stdio MCP. Step 4 (`_discovery_run.py`) hardcodes `STEP4_DEFAULT_BUDGET` and drops scout `model_overrides`; Step 6 (`vault_svc.py`, `_vault_helpers.py`) ignores snapshot budgets, `model_overrides`, and `v7_critic_tier`; and `_run_adapters.py:_compute_run_state_with_overlays` double-counts prior `raise-budget` extensions when re-hydrating cloned run rows from `rows[-1]`.
4. **No Agent-vs-Human Split in Errors:** CLI, HTTP, MCP, and Web errors do not separate agent-executable fixes (`uv sync --extra sdk`, switching provider) from human-only TTY actions (`claude auth login`, `agy`, `opendv secrets set --prompt`).
5. **Lease Expiry on Long Turns & Secret Leakage Hazards:** SQLite `leases` hardcode `ttl_seconds=120` (shorter than `budget.timeout_seconds`), expiring prematurely during long Step 4/6 turns; `cli_subprocess_base.py` forwards ambient `GEMINI_API_KEY` into `agy` while short-circuiting non-secret provider env vars when `api_key` is set; `subprocess_runner.py:415-429` inspects only `stderr` before checking stdout NDJSON `is_error: true`; and `_pii_redact.py` scrubs PII without scrubbing API credentials (`sk-*`, `AIza*`, `dapi*`, `Bearer *`).

## Goals

- Deliver a lightweight Layer-4 readiness service reporting four per-provider states (`MISSING_PREREQ`, `CONFIGURED_UNVERIFIED`, `VERIFIED`, `AUTH_FAILED`) plus active-run locks across `agy`, `claude-cli`, `claude`, and `gemini`, finishing warm offline Tier-1 checks in `< 50ms` via `importlib.util.find_spec` at zero tokens (§2.1–2.2).
- Switch keyring and flat `secrets.json` storage to user-global scope (`service_name = "opendv"`), persist keyring-only `secret_keys.json` under the single existing `secrets.json.lock` (`owner_only=True`), persist non-secret `readiness.json` via default `owner_only=True` `atomic_write_text` without cross-process locking, and isolate host OS keyrings across in-process tests, child CLI/MCP/Playwright/contract-export processes, and `export_openapi_schema()` (§1.1, §2.1, §4.2, §4.4).
- Wire project snapshots and `model_overrides` across `init_project`, atomic `PATCH /api/v1/projects/{project_id}/settings` (new runs), default Step 4/6 launches (REST/CLI/Web/MCP), Step 4 coordinator + scouts, and Step 6 builds/resumes; fix `raise-budget` double-counting once in `_compute_run_state_with_overlays` (`rows[0]`); wrap real runners in minimal `ReadinessRecordingHarness`; bound multi-turn job lease TTLs via `compute_job_lease_ttl(...)` + synchronous live `raise-budget` renewal; keep `agy` on OAuth/ADC; and scrub credentials before PII rules (§1.2, §2.3, §4.1, §4.3).
- Provide opt-in Tier-2 auth verification (`POST /api/v1/agents/readiness/test`, `doctor --probe`), offline default model catalogs (`settings models` and Web **Agent Model Matrix** `<datalist>`), and copyable native CLI auth/secret commands (§2.4, §4.2, §4.4–4.5).
- Propagate `ProblemDetails.remediation` (`34` closed `ErrorCode`s unchanged, `4`-field `RemediationAction`) across synchronous HTTP errors, `ProviderReadinessRecord`, `DoctorResponse`, CLI, stdio MCP, Web alerts, and `.agents/skills/open-dv-workflow/` (§3.1–3.3).
- Achieve full non-UI CLI parity (`_commands_settings.py`, `11` groups, `53` subcommands, `pyproject.toml:37` routed through `opendv.cli.main:main`) while keeping Web `/settings` User-Global, every module `< 5,000` `cl100k_base` tokens, and all CI/architecture/E2E gates green (§4.4–4.5).

## Non-Goals

- Built-in `.env` file parsing or mutating `os.environ` via `load_dotenv()` (operators bind credentials once via `opendv secrets set --prompt`, Web Settings, shell environment variables, or `uv run --env-file .env opendv ...`).
- Salted credential/binary fingerprinting (`install_salt`, `verification_fingerprint`, `os.stat`), dual epoch/seq counters, cross-process `readiness.json` file locking or Win32 read-retry loops, live model-catalog fetching (`models_only` / `settings models --refresh` / Web **Refresh models**), `claude-cli` `loginExpiresAt` expiry math or `external_api_key_helper` state, or custom `ANTHROPIC_BASE_URL` URL parsers (`readiness.json` is a minimal best-effort status cache cleared on secret/settings mutations, and `default_model_options(provider)` supplies offline model suggestions).
- Deep Step 6 CEGAR `S6-02` Pause / `S6-04` `UNCERTIFIED_DRAFT` candidate & V7 resume hydration and pre/post-checkpoint `consumed_seq` watermark refactoring (tracked separately in GitHub Issue `#247` for immediate follow-up after this feature lands).
- Server-spawned Web OAuth login endpoints (`POST /api/v1/agents/auth/login`) or a wrapper `opendv auth login` CLI group (operators run native `claude auth login`, `agy`, or `uv run opendv secrets set <KEY> --prompt` directly and verify via `opendv doctor --probe` or Web **Test**).
- Web `/settings` dual-scope Active Project editing UI (`ProjectSettingsScopeBar` / `projectSettingsDraft`; operators update existing project snapshots via `PATCH /api/v1/projects/{project_id}/settings` or `opendv project settings {show,set}`, and Web Step 4/6 pages initialize launch defaults from `activeProject.settings_snapshot`).
- Dedicated `POST /api/v1/settings/profiles/{name}/test` endpoint, Web/CLI Databricks `http://` input rewriting refactors, or per-route remote `binary_path` basename redaction (Web Settings and CLI `settings profile test` reuse existing `POST /api/v1/sources/inspect` / `inspect_source`).
- Web SSE `RUN_FAILED` remediation payload plumbing or `RemediationAction.kind` classification (`ProblemDetails.remediation` attaches strictly to synchronous `OpenDVError`, `ProviderReadinessRecord`, and `DoctorResponse`, while passive `ReadinessRecordingHarness` downgrades `readiness.json` on mid-turn auth errors).
- Retroactively re-budgeting paused `HOLD_CHECKPOINTED` runs via `PATCH /api/v1/projects/{project_id}/settings` (`PATCH` governs new runs; paused Hold runs use `opendv ontology control --action raise-budget` / `opendv vault control --action raise-budget`), custom `@model_serializer` on `DoctorResponse`, adding a 35th `ErrorCode`, or automatic live LLM probes on `GET` / mount.

## Critical User Journeys (CUJs)

### CUJ 1: First-Time Web Settings Inspection, Model Selection & Manual Provider Check

- **Given:** A clean Linux or Windows host with `claude-cli` installed, `agy` missing, `claude`/`gemini` SDK packages not installed, and no `readiness.json` file yet.
- **When:** The operator opens `/settings` (Provider tab), selects `claude-cli`, saves settings, and clicks **Test**.
- **Then:**
  - On page load, zero live LLM probes run; `agy` and SDK providers render `MISSING_PREREQ` (`.pill-err`) naming every missing binary, SDK extra, or API key at once, while `claude-cli` shows `CONFIGURED_UNVERIFIED` (`.pill-warn`) with an unverified banner restricted to the selected provider and offline `default_model_options("claude-cli")` populated in the **Agent Model Matrix** `<datalist>`.
  - Clicking **Test** sends `POST /api/v1/agents/readiness/test` (`{"provider": "claude-cli"}`), returning HTTP `200 OK`; if `claude auth status --json` reports `loggedIn: false`, the card renders `AUTH_FAILED` with scrubbed error summary, `<RemediationList />`, copyable `claude auth login`, and inline masked `ANTHROPIC_API_KEY` bind controls.
  - After signing in or binding a key and clicking **Test**, `readiness.json` records `VERIFIED` (`.pill-ok`).

### CUJ 2: Passive Verification & Long-Turn Active-Run Suppression

- **Given:** `agy` is `CONFIGURED_UNVERIFIED` and the operator starts a Step 4 discovery or Step 6 CEGAR build whose turn runs past `120s`.
- **When:** Another client checks readiness or clicks **Test** (`POST /api/v1/agents/readiness/test`) for `agy` at `t = 150s`, and the live LLM turn completes (or fails auth) at `t = 180s`.
- **Then:**
  - `acquire_project_job_lease` claims `active_job_lease:<project_id>` with `ttl_seconds = compute_job_lease_ttl(effective_max_turns, effective_timeout_seconds)` (bounded at `<= 86_400s` and renewed synchronously on live `raise-budget`, while `is_lease_row_live` clears crashed PIDs in `0s`), so the manual `agy` probe is rejected fail-closed with `409 PROJECT_JOB_ACTIVE` and `/settings` disables **Test** when `active_run` is `true`.
  - `ReadinessRecordingHarness` offloads best-effort `readiness.json` writes via `asyncio.to_thread(...)`, stamping `VERIFIED` only after a real `AgentTurnResult` succeeds or downgrading to `AUTH_FAILED` with credential-scrubbed error text and `remediation` on `AGENT_NOT_CONFIGURED` (skipping disk writes when `--env-first` or non-matching project `secret_precedence` is active).

### CUJ 3: Autonomous CLI Agent Handling Synchronous & Post-Turn Remediation

- **Given:** An external coding agent following `.agents/skills/open-dv-workflow/` runs `uv run opendv --json ontology construct --project am_demo --wait` when `harness_provider` is `claude` without `--extra sdk` or `ANTHROPIC_API_KEY` (or hits an auth failure mid-turn and then checks `opendv --json doctor`).
- **When:** Synchronous preflight exits non-zero (`CliExitCode.VALIDATION_ERROR` = `2` for HTTP `422` `DRIVER_MISSING` / `AGENT_NOT_CONFIGURED`) or post-turn diagnostics inspect `readiness.json`.
- **Then:**
  - `ProblemDetails.remediation` and `ProviderReadinessRecord.remediation` carry a single `ErrorRemediation` (`summary` + `actions` with `actor`, `label`, `command`, `requires_tty`), while `DoctorResponse.remediation` carries `list[ErrorRemediation]` aggregating active-provider, untrusted-workspace, and enabled-MCP remediations.
  - Synchronous failures surface under `CliEnvelope.problem.remediation` in `--json` stdout and plain stderr (`[Agent]` vs `[Human action required]`): e.g., `uv sync --extra sdk` or provider switch (`actor: "agent"`) vs `uv run opendv secrets set ANTHROPIC_API_KEY --prompt` for `claude` (or `claude auth login` / `agy` for CLI providers; `actor: "human"`, `requires_tty: true`). Mid-turn auth failures downgrade `readiness.json` passively so follow-up `opendv --json doctor` checks surface full remediation without pasting secrets into argv or chat.

### CUJ 4: Full Non-UI CLI Configuration & User-Global Keyring

- **Given:** A headless operator on Linux configures `open-dv` completely from the terminal across server restarts.
- **When:** The operator stores `ANTHROPIC_API_KEY` and Databricks tokens via `opendv secrets set <KEY> --prompt`, sets budgets (`--max-turns`, `--max-tokens`, `--timeout-seconds`), `--model-override STANDARD_WORKER=claude-sonnet-4-6`, creates/tests a connection profile (`opendv settings profile set|test`), lists default models via `opendv settings models`, and runs `opendv secrets list` + `opendv --api-url http://127.0.0.1:8420 --json doctor --probe`.
- **Then:**
  - `secrets list` persists `ANTHROPIC_API_KEY` across restarts via `secret_keys.json` without exposing values, and `settings profile test --name <name>` reuses `inspect_source` / `POST /api/v1/sources/inspect`.
  - `settings models` returns offline `default_model_options` with zero network calls, and `doctor --probe` probes the active `harness_provider` via `POST /api/v1/agents/readiness/test` and merges the result into `GET /api/v1/system/doctor`.

### CUJ 5: Updating Project Settings for New Runs & Step 4/6 Runtime Wiring

- **Given:** Project `am_demo` was created with `balanced` defaults and `agy`, and the operator updates project execution settings via `uv run opendv project settings set --project am_demo --harness-provider claude-cli --cegar-policy strict --max-turns 12 --model-override dv-semantic-critic=claude-opus-4-6` (or `PATCH /api/v1/projects/am_demo/settings`).
- **When:** Default Step 4 (`opendv ontology construct --project am_demo`, MCP `ontology_construct`, or Web Step 4 Launch) or Step 6 (`opendv vault build --project am_demo`, MCP `vault_build`, or Web Step 6 Launch) executes on `am_demo` without explicit `--policy` / `--discovery-mode` overrides.
- **Then:**
  - Setting `cegar_policy="strict"` auto-promotes `v7_critic_tier` to `FRONTIER_CRITIC` atomically under `BEGIN IMMEDIATE` (rejecting explicit conflicting `STANDARD_WORKER` and rejecting updates while a lease is active with `409 PROJECT_JOB_ACTIVE`).
  - Default Step 4/6 launches inherit `settings_snapshot.cegar_policy="strict"` and `settings_snapshot.discovery_mode`, apply snapshot `max_turns=12`, coordinator + scout `model_overrides`, and `v7_critic_tier` at runtime (injecting optional stored `ANTHROPIC_API_KEY` for `claude-cli` when configured), and `_run_adapters.py:_compute_run_state_with_overlays` reads base budgets from `rows[0]`.

## Technical Plan (Architecture)

### Architecture Overview & DAG Boundaries

Business logic stays inside Layers 1–4 (`models`, `sources`, `agents`, `service`); Layer 5 (`api`, `cli`) and `web/` are thin transports. `cli` never imports `api`, `opendv.agents`, or `opendv.sources` (`tests/architecture/test_import_contracts.py`); remote `--api-url` commands delegate via HTTP to the server's Layer 4 state.

```text
  Web Workbench (/settings, Alerts)  ──HTTP──────┐
  opendv --api-url <url> (CLI)       ──HTTP──────┴──▶ FastAPI Layer 5 (_routes_system, routes_projects, _routes_vault_storage)
                                                                 │
  opendv <cmd> (in-process CLI)      ────────────┐               ▼
  opendv mcp serve (stdio MCP)       ────────────┴──▶ Layer 4: OpenDVService Facade (+ _app_readiness_mixin)
                                                        ├─ KeyringSecretStore (+ _secret_manifest.py, secret_keys.json)
                                                        ├─ HarnessReadinessService (+ _remediation.py, readiness.json)
                                                        └─ SettingsStore / Projects / Discovery / Vault (budget-sized lease TTL)
                                                           ├─▶ Layer 2: sources/* (profiler, adapters, _extractors)
                                                           ▼
                                                      Layer 3: Runners, Probes & Redaction
                                                        ├─ harness_probes.py (Tier-2 auth probes, default_model_options)
                                                        ├─ cli_subprocess_base.py (is_auth_error, run_cli_subprocess_capture)
                                                        └─ SubprocessHarnessRunner / SdkHarnessRunner / _pii_patterns.py
                                                                       │
                                                                       ▼
                                                      Layer 1: models/* (DTOs, Policy, Errors)
```

### Empirical Probe Baseline

Live probes executed against the target providers on `2026-11-25` established four concrete protocol rules encoded in Subsystems 1–4:

- **`agy` auth verification (`agy v1.5.14`):** `agy models` exited `0` even in an isolated empty user profile with invalid `AGY_ACCOUNT`, so manual **Test** runs a single bounded `--print=Reply OK.` ping to verify inference auth.
- **`agy` key isolation (`GEMINI_API_KEY` non-effect):** Per Antigravity official installation guidance, `GEMINI_API_KEY` alone does nothing for `agy`, and forcing `--settings '{"modelProvider":"gemini"}'` hijacks signed-in OAuth sessions—so `agy` never receives `GEMINI_API_KEY` overrides.
- **`claude auth status --json` vs API-key verification:** Returns `loggedIn: false` (`exit 1`) when logged out and `loggedIn: true` when signed in via OAuth, **but returns `loggedIn: true` (`exit 0`) locally even with an invalid `ANTHROPIC_API_KEY`**. Manual **Test** on `claude-cli` therefore calls zero-token `GET /v1/models?limit=1` whenever Open-DV resolves an `ANTHROPIC_API_KEY`, and uses `claude auth status --json` (`loggedIn`) when no API key is resolved.
- **Anthropic vs Gemini `models.list()` auth check (`0` tokens):** With invalid keys, `anthropic` returns `AuthenticationError` HTTP `401` while `google-genai` returns `ClientError` HTTP **`400 INVALID_ARGUMENT`** carrying `API_KEY_INVALID` (not `401`/`403`); valid keys return `200 OK` at zero tokens.

### Subsystem 1: User-Global Secrets, Keyring Manifest & Layer 1/2 Validators

#### 1.1 User-Global Keyring, Single-Lock Manifest & Test Isolation

**Modules:** `src/opendv/service/secrets.py`, `src/opendv/service/_secret_manifest.py`, `src/opendv/service/__init__.py`, `src/opendv/service/app_service.py`, `src/opendv/service/workflows/_harness_factory.py`, `src/opendv/api/server.py`, `src/opendv/cli/export_contracts.py`, `tests/conftest.py`, `tests/helpers/secret_backends.py`, `tests/service/test_secrets_settings.py`, `tests/cli/test_cli_exit_codes_and_mcp_stdio.py`, `web/playwright.config.ts`, `web/e2e/live_smoke.ts`

- **User-Global Keyring & Single-Lock `secret_keys.json`:** Replace workspace-digest keyring scoping (`opendv:{sha256(OPENDV_HOME)}`) with a single user-global namespace (`service_name = "opendv"`, aligning `probe_keyring_available` at `secrets.py:64` to probe `("opendv", "__opendv_probe__")`), flatten `secrets.json` to `{"schema_version": "2.0", "secrets": {...}}` (emitting a clear `INTERNAL_SERVER_ERROR` message when legacy `"workspaces"` appears without `"secrets"`), remove in-memory `self._known_keys` / `self._mem_lock` (avoiding cross-process split-brain between in-process CLI calls and `:8420`), and remove `resolve_workspace_namespace` from `src/opendv/service/secrets.py` and `src/opendv/service/__init__.py` (keeping `workspace_root: Path | str | None = None` as an ignored optional parameter on `KeyringSecretStore.__init__` alongside `settings_store` / `keyring_backend` at `secrets.py:108-121` and `OpenDVService.__init__` at `app_service.py:98-118`). Extract `secret_keys.json` manifest I/O and `resolve_gemini_api_key_with_source(...)` into `src/opendv/service/_secret_manifest.py` so `secrets.py` stays well below `5,000` tokens. Keep existing `<OS_USER_STATE>/opendv/` paths and `owner_only=True` layout untouched for `settings.json`, `mcp_servers.json`, and `secrets.json`. Expose public `effective_env() -> Mapping[str, str]` and `is_env_first_override_active() -> bool` (wrapping `_CLI_ENV_FIRST.get()`) on `KeyringSecretStore` for `_harness_factory.py` and `readiness.py`.
- **Manifest Serialization, ACL & Lock Hierarchy:** Persist sorted keyring-stored key names solely in `<OS_USER_STATE>/opendv/secret_keys.json` (`{"schema_version": "2.0", "keys": [...]}`, `owner_only=True`, enforcing `verify_owner_only_permissions(self.secret_keys_path)` when present and failing closed with `INTERNAL_SERVER_ERROR` on corrupt JSON matching `secrets.json` at `secrets.py:217-236`) guarded under the **existing single `secrets.json.lock` (`self._lock_path`)**:
  - Have `_store_delete(..., backend_kind)` return `keyring_deleted: bool`: when `backend_kind == "keyring"` succeeds (`delete_password` succeeds or raises `PasswordDeleteError`), return `True` immediately without touching `secrets.json`; only when `backend_kind == "user_state_file"` or keyring raises headless fallback errors (`NoKeyringError`/`InitError`/`KeyringLocked` with `allow_headless_fallback=True`) run fail-closed `_delete_from_user_state_file(clean_key)` and return `False`.
  - Scope `secret_keys.json` strictly to keyring-stored keys:
    - In `set_secret`, when `used_backend == "keyring"`, add `clean_key` to `secret_keys.json` under `self._lock_path` and—if `self.secrets_path.exists()`—run best-effort `_delete_from_user_state_file(clean_key)` wrapped in `try / except OpenDVError:` warning log so rotated keyring keys never resurrect stale values from `secrets.json`.
    - In `delete_secret`, when `keyring_deleted` is `True`, prune `clean_key` from `secret_keys.json` (if `self.secret_keys_path.exists()`) under `self._lock_path`, and—if `self.secrets_path.exists()`—run the same best-effort `_delete_from_user_state_file(clean_key)` wrapped in `try / except OpenDVError:`.
  - **Simplified `list_secret_summaries(keys=..., *, include_stored: bool = True)`:**
    - Track `requested_keys: set[str]`. When `include_stored=False`, skip reading `secrets.json` and `secret_keys.json`; furthermore, when `include_stored=False` and resolved `precedence == "env_first"`, check `_read_env_secret(env, k)` **first** per requested key, emitting `SecretSummary(key=k, present=True, backend="env")` immediately and calling `self.effective_backend()` / `_store_get` lazily at most once only for keys absent from env (so `opendv --env-first doctor` never touches a locked OS keyring when env supplies all queried keys).
    - When `include_stored=True`, resolve `backend_kind: SecretBackend = self.effective_backend()` **once** upfront (before acquiring `self._lock_path`): load `secret_keys.json` keys when `backend_kind == "keyring"`, or `secrets.json` keys when `backend_kind == "user_state_file"`. If `backend_kind == "keyring"` and `self.secrets_path.exists()`, probe `self._active_keyring().get_password("opendv", "__opendv_probe__")` once upfront (or if any `_store_get` raises `(NoKeyringError, InitError, KeyringLocked)`): when `self._allow_headless_fallback` is `True`, flip `backend_kind = "user_state_file"` and merge keys from `secrets.json` under `self._lock_path` regardless of whether `secret_keys.json` was non-empty (else raise `INTERNAL_SERVER_ERROR`; raise `INTERNAL_SERVER_ERROR` on `(KeyringError, OSError, RuntimeError)`).
    - For each key `k`: if `k not in requested_keys` and store lookup returns `None`, emit `SecretSummary(key=k, present=True, backend="env")` if `env_val is not None` and **omit `k`** if `env_val is None` (no locked re-verify auto-prune dance; `delete_secret` prunes `secret_keys.json`). Keys in `requested_keys` are always emitted (including `present=False, backend="unset"`).
  - **Lock Ordering:** Never invoke `effective_backend()` / `_current_settings()` (`settings.json.lock`) while holding `self._lock_path` (`secrets.json.lock`): resolve `backend_kind = self.effective_backend()` **before** acquiring `self._lock_path` across `set_secret`, `delete_secret`, and any store lookup path of `list_secret_summaries` / `get_secret_with_source` (only *after* checking the `env_first` short-circuit), threading `backend_kind: SecretBackend` into `_store_get`, `_store_set`, and `_store_delete`.

## Alternatives Considered

1. **Salted Credential/Binary Fingerprints (`install_salt`, `verification_fingerprint`) & Dual Epoch/Seq Counters vs. Minimal Eager-Cleared `readiness.json`:**
   - *Pros:* Detects out-of-band `os.environ` API-key edits or CLI binary upgrades without a re-test.
   - *Cons & Rejection:* Introduced `install_salt` write races, `os.stat` `OSError` hazards, `ANTHROPIC_BASE_URL` normalizers, lock deadlocks, and probe-vs-run epoch TOCTOU complexity for a single-user local diagnostic cache. Chosen: minimal 4-field `readiness.json` (`VERIFIED`/`AUTH_FAILED` + timestamps/summary) cleared eagerly on `set_secret` / `delete_secret` / `update_settings` and skipped on `--env-first` or non-matching project precedence.
2. **Live Model-Catalog Discovery (`models_only=True`, `settings models --refresh`, 4 Provider Parsers) vs. Offline `default_model_options`:**
   - *Pros:* Lists newly released provider models in `<datalist>` after a network refresh.
   - *Cons & Rejection:* Required 4 provider-specific catalog parsers/filters, `models_refreshed` persistence rules, and extra UI/CLI state when `<input list>` already accepts any custom model ID as free text. Chosen: deterministic offline `default_model_options(provider)` for `<datalist>` and `opendv settings models`, keeping Tier-2 probes focused strictly on boolean auth verification.
3. **Bundling Deep Step 6 CEGAR `S6-02`/`S6-04` Resume Hydration & Watermarks into This PR vs. Dedicated Follow-Up (`#247`):**

   - *Cons & Rejection:* Touched 6 extra CEGAR/vault modules with subtle V7/energy/signal-replay interactions orthogonal to harness readiness and CLI parity. 4. **Auto-Probing Live LLM Endpoints on Mount / `GET`, Built-In `.env` Loading, or Wrapper `opendv auth login` vs. Offline Tier-1 + Native Commands:**
   - *Pros:* Fewer manual steps on initial setup.
   - *Cons & Rejection:* Live probes on `GET` violate HTTP idempotency and burn `agy` quota; in-process `.env` loading creates untrusted-repo hijacking hazards; and `opendv auth login` duplicates native `claude auth login`, `agy`, and `opendv secrets set --prompt` while adding a 12th CLI group.    - *Cons & Rejection:* `schemas/v2/error-codes.json` locks `34` codes, and SSE `RUN_FAILED` plumbing touches 4 extra async task/stream modules when preflight `422` errors already carry `ProblemDetails.remediation` and mid-turn `401`s passively update `readiness.json` (`GET /api/v1/agents/readiness` / `opendv doctor`). ## Non-Functional Requirements

- **Performance & Latency:** Warm offline Tier-1 readiness checks finish in `< 50ms` via `importlib.util.find_spec`, `env_first` keyring short-circuiting, and deduplicated 3-key lookup at zero tokens (§1.1, §2.2). Tier-2 probes enforce a `15s` deadline with explicit client/subprocess timeouts (§2.4).
- **Security & Privacy:** Zero raw secret values persisted in `settings.json`, `readiness.json`, `secret_keys.json`, `ProblemDetails.remediation`, CLI argv, or Git files (`<OS_USER_STATE>/opendv/` secured automatically via default `owner_only=True` `atomic_write_text`). Compiled credential patterns run before numeric PII rules (§2.3). Presence-based `has_proxy_forwarding_headers` rejects proxied loopback traffic (`403 LOOPBACK_ORIGIN_FORBIDDEN`) when `not allow_remote` (§4.2). `RevokeTrustedWorkspaceReq` blocks blank, control-char, and normalized `"//"` UNC/device paths (§4.1, §4.3). Child-process tests, `export_openapi_via_subprocess`, and Playwright servers set `PYTHON_KEYRING_BACKEND=keyring.backends.null.Keyring` so host OS keychains are never touched (§1.1, §4.4). Tier-2 CLI probes run inside `IsolatedTempCwd()` with `build_isolated_child_env(..., step="step6")`, `stdin=DEVNULL`, and unconditional `finally: if proc is not None: await reap_process_tree(proc, job_handle=job_handle)` containment (§2.4).
- **Concurrency & Lifecycle Safety:** Bounded `compute_job_lease_ttl` (`<= 86_400s`, Layer-1 `le=500` / `le=7200` bounds) + synchronous `renew_lease` (`contextlib.suppress(OpenDVError)`) on live (`QUEUED`/`RUNNING`/`HOLD_REQUESTED`) `raise-budget` complements `0s` PID-liveness cleanup (§1.2, §2.3). `ReadinessRecordingHarness` and `test_agent_readiness` offload `readiness.json` I/O via `asyncio.to_thread` guarded in-process by `threading.Lock` + best-effort default `owner_only=True` `atomic_write_text` (skipping writes on transient read `OSError` rather than wiping sibling providers and falling back to `CONFIGURED_UNVERIFIED` on read errors), releasing `self._lock` before calling `get_provider_statuses()` / `get_readiness()` and skipping writes on `transient_error`, `DRIVER_MISSING`, or non-global `--env-first`/`OPENDV_SECRET_PRECEDENCE`/project-precedence runs (§2.1–2.4). `SettingsStore.update_settings` holds `self._settings_lock_path`; `KeyringSecretStore` eliminates split-brain `_known_keys` and resolves `backend_kind` before acquiring `secrets.json.lock` (§1.1, §4.3); `PATCH /api/v1/projects/{project_id}/settings` checks `active_job_lease:{project_id}` and mutates snapshots atomically under `BEGIN IMMEDIATE` (§4.3); and `_compute_run_state_with_overlays` reads starting budgets from `rows[0]` (§4.3).
- **Architecture, Static Gates & Token Budgets:** Every modified/created `.py`, `.ts`, and `.tsx` file remains strictly `< 5,000` `cl100k_base` tokens (`tests/architecture/test_module_token_budget.py`). New and modified Python modules (all new and modified Python modules under `src/opendv/`) obey zero blind `BLE001`, zero `S110` `try-except-pass`, zero `"expanduser"` string literals/docstrings across **all** production modules (`test_hardening_t14.py:43, 109-113`), zero loopback IP literals, zero non-exempt URLs (`test_no_hardcoded_literals.py`), zero `cli -> api/agents/sources` imports (`test_import_contracts.py`), DI seams (`test_llm_seam_guard.py`), `< 8`-line clone budget (`test_clone_detection.py`), and `test_mock_guards.py`.

## Risks & Limits

- **Best-Effort `readiness.json` Cache (No Cross-Process Lock or Fingerprints):** Because `readiness.json` intentionally omits salted credential/binary fingerprints, cross-process file locks, and Win32 read-retry loops, rotating an `os.environ`-only API key outside `opendv secrets set|delete` retains cached `VERIFIED`/`AUTH_FAILED` until the next turn or manual **Test** (`opendv doctor --probe`), and simultaneous CLI + `:8420` writes or transient Win32 read `OSError`s either skip the write (preserving sibling providers) or fall back cleanly to `CONFIGURED_UNVERIFIED` on read. *Mitigation:* `set_secret`, `delete_secret`, and `update_settings` clear `readiness.json` eagerly; `--env-first` skips disk writes; in-process `self._probing` prevents double-click/concurrent probe storms; failed turns immediately downgrade to `AUTH_FAILED`; and re-verification happens automatically on the next real turn or manual **Test**.
- **Deferred Deep Step 6 CEGAR Resume Hydration (GitHub Issue `#247`):** Pre-existing Step 6 `S6-02` Pause / `S6-04` `UNCERTIFIED_DRAFT` candidate hydration and `consumed_seq` signal-watermark edge cases remain unchanged in this PR. *Mitigation:* Tracked in GitHub Issue `#247` and scheduled as the immediate next implementation task once this feature passes all 5 gates.
- **Pre-Release Schema Tightening & Flat `secrets.json`:** Tightening `WorkspaceSettings` / `ProjectSettingsSnapshot` validation (`max_turns <= 500`, `timeout_seconds <= 7200`, `VALID_MODEL_OVERRIDE_TARGETS`) and flattening `secrets.json` from `{"workspaces": {...}}` to `{"secrets": {...}}` intentionally rejects legacy local `settings.json`, `secrets.json`, `project.sqlite`, or `.opendv.zip` files. *Mitigation:* Share `_parse_settings_snapshot` (`ValidationError -> INTERNAL_SERVER_ERROR`) across `state_store.py:107` and `update_project_pointers`, and emit a clear `INTERNAL_SERVER_ERROR` message when legacy `"workspaces"` appears in `secrets.json` without `"secrets"`.
- **Upstream CLI Drift & `agy` Ping Quotas:** `agy v1.5.14` (`--sandbox --disable-slash-commands --print-timeout --print=Reply OK.`) and `claude auth status --json` are external CLI contracts, and manual `agy` **Test** spends minimal inference quota. *Mitigation:* Gate `--print` strictly behind explicit manual **Test** / `doctor --probe`, enforce `15s` timeouts + unconditional `reap_process_tree`, and parse CLI JSON defensively.
- **Module Token-Budget Hotspots:** `src/opendv/service/state_store.py` (`572` LOC), `src/opendv/service/app_service.py` (`555` LOC), `src/opendv/models/errors.py` (`548` LOC), `src/opendv/cli/commands_core.py` (`526` LOC), `src/opendv/service/workflows/_discovery_sources.py` (`525` LOC), `src/opendv/agents/subprocess_runner.py` (`500` LOC), `src/opendv/service/workflows/_run_adapters.py` (`499` LOC), `src/opendv/service/workflows/vault_svc.py` (`490` LOC), `src/opendv/api/_security.py` (`488` LOC), `src/opendv/cli/_client.py` (`479` LOC), `src/opendv/service/secrets.py` (`461` LOC), `web/src/pages/Step2Sources.tsx` (`633` LOC), `web/src/components/SourceRecoveryDialogs.tsx` (`595` LOC), `web/src/pages/Step4Discovery.tsx` (`577` LOC), `web/src/App.tsx` (`564` LOC), `web/src/store/projectStore.ts` (`539` LOC), `web/src/pages/Step6Vault.tsx` (`537` LOC), and `web/src/store/selectors.ts` (`525` LOC) sit near `5,000` tokens. *Mitigation:* Extract `_secret_manifest.py`, `_remediation.py`, `_app_readiness_mixin.py`, `readiness.py`, `_harness_factory.py`, `wire_dtos_readiness.py`, `harness_probes.py`, `_commands_settings.py`, `RemediationList.tsx`, and `HarnessReadinessCard.tsx` upfront (keeping `trust_workspace` in `_client.py` if splitting `_client_settings.py` so `ALLOWLISTED_EXPANDER_MODULES` stays untouched).
