## §1. Locked Product & Platform Decisions (`D1`–`D28`)

### §1.1 Round 1 Decisions (`D1`–`D10`) — Unified Wizard Flow & Semantics

| ID | Decision | Normative Rule |
| :--- | :--- | :--- |
| **D1** | **Single-Pass Agent Draft + Live Q&A Cascade** | Step 4 executes `@term-scout ➔ @domain-clarifier ➔ @ontology-architect` in a single coordinated pass producing one unified proposal draft + `Q1..Qn`; changing any Q&A answer cascades updates through dependent proposal chips live. |
| **D2** | **Dual FIBO Q&A Channels** | Combine structured `@domain-clarifier` clarification questions (`Q1..Qn`) with an interactive **Ask FIBO & Sources** panel (`POST /sessions/{id}/fibo-qa`) returning cited answers and 1-click `SuggestedDeltaAction`s. |
| **D3** | **Beyond-FIBO Synthesis + Optional `skos:broadMatch`** | Agents freely synthesize custom domain entities, relationships, and typed attributes (`grounding_origin="STRUCTURED_SCHEMA"` or `"DOCUMENT_OBSERVED"`), with optional `skos:broadMatch` links to FIBO rather than forcing artificial `exactMatch` fits. |
| **D4** | **Zero Mention-Count Floor on Unstructured Docs** | Never prune document concepts by occurrence count; single-mention rules, SLAs, thresholds, and obligations (`1x · Semantic`) qualify automatically when semantically load-bearing. |
| **D5** | **Parent-to-Child Cascading Cherry-Pick + Inline Edits** | Unchecking a parent concept automatically cascades-uncheck to dependent attributes and links; users can inline-edit concept names, attribute data types, and mappings before staging. |
| **D6** | **Bounded Samples (`<= 5` Masked in Prompt, `<= 50` Local Preview)** | Step 3a local preview caps at `<= 50` rows; LLM agent prompts receive at most `<= 5` PII-masked sample values per column (`<MASKED_PII>`) and strictly exclude `do_not_send_to_agent` sources. |
| **D7** | **Unchecked Opt-In `MAJOR` Breaking Suggestions** | Schema-drop or breaking changes surface in a distinct red-bordered **`MAJOR · Opt-In`** bucket, **unchecked by default**, so routine runs preserve non-destructive `MINOR` SemVer evolution unless explicitly opted in. |
| **D8** | **Step 3 ➔ Step 6 Fast-Forward** | Users starting from an already-finalized ontology baseline can fast-forward directly from Step 3 (Preview) to Step 6 (DV 2.0 Build & Run) without creating empty ontology versions. |
| **D9** | **Step 5 Export-Only Exit** | Step 5 supports standalone `.yaml`/`.json`/`.ttl` ontology export (`Export Ontology Only`) and CAS commit without forcing a DV pipeline run. |
| **D10** | **Unified Step 6 Console + Drift Sync Loopback** | Step 6 unifies multi-dialect lowering (`DuckDB` / `Databricks Delta`), live 7-pill (`00..06`) execution console (projected over internal `STAGE_00..07` per [`docs/28 §4.4`](28-unified-ontology-pipeline-design-and-plan.md)), 5-Zone (`Z0–Z4`) SQL preview, **`Explore Generated DV 2.0 Schema ➔`**, and **`↺ Sync Drift to Step 4`** for Stage 02 unmodeled drift (`UF-1..UF-5`). |

## §4. Real-Agent + Real-Data UAT Mandate & Stop-and-Notify Protocol

1. **Zero Mocks / Zero Deterministic Substitutions**: Every UAT scenario (`SCN-01`..`SCN-13`) and sign-off item (`UAT-01`..`UAT-30`) MUST run against **real downloaded public datasets/PDFs** and **real working LLM agents** (`mode="agent"`). Any run carrying `mode=deterministic`, mock adapters, recorded/canned LLM responses, or hardcoded domain rules is **invalid** for UAT sign-off.
2. **Mandatory Readiness & Canary Preflight**: Before executing `SCN-01`..`13`, Phase 6 starts `uv run opendv serve --host 127.0.0.1 --port 8420` (restarting any stale daemon cleanly or isolating on a fresh port) with zero test-double flags, runs `probe_providers_readiness()` across configured providers (`agy`, `agy-cli`, `antigravity`, `claude-cli`, `claude`), and executes a live 1-turn canary LLM call.
3. **Mandatory Stop-and-Notify Escalation**: If **none** of the real agent providers succeed in the readiness probe and live canary call, **STOP UAT IMMEDIATELY** and escalate to the user with exact readiness diagnostics, CLI error output, and remediation steps. Never proceed with fallback rules or fake responses.
